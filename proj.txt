# Project Specification: Native On-Device Android Manga & Webtoon Screen Translator

You are a Senior Android Systems & Computer Vision Engineer. Build a complete, production-grade, 100% offline Android screen-translation application tailored for reading raw Japanese manga, Chinese manhua, and Korean manhwa in any reader app (Mihon, Kotatsu, browsers, etc.).

Do not use placeholders, TODO stubs, or simplified mock logic. Implement every file, algorithm, coroutine state machine, and view class completely.

---

## 1. Target SDK, Compatibility & Tech Stack

- **Android SDK**: `minSdk = 30` (Android 11, baseline for `AccessibilityService.takeScreenshot()`), `targetSdk = 36` (Android 16), `compileSdk = 36`.
- **Language & Concurrency**: Kotlin 2.1+, Kotlin Coroutines (`SupervisorJob`, `Dispatchers.Main.immediate`, `Dispatchers.Default`), Kotlin Flows.
- **UI Stack**:
  - **Main Setup & Model Manager Activity**: Jetpack Compose (Material 3) for toggling service permissions, pre-downloading language packs, and tuning debounce timers.
  - **Screen Overlays**: Native Android custom `View` + `Canvas` + `StaticLayout` attached directly to `WindowManager` via `TYPE_ACCESSIBILITY_OVERLAY`. Do NOT use Jetpack Compose inside the accessibility overlay windows; keep overlay memory footprint and frame-hide latency under 2ms.
- **ML Dependencies (100% On-Device, Zero Cloud Keys)**:
  - `com.google.mlkit:text-recognition-japanese:16.0.1`
  - `com.google.mlkit:text-recognition-chinese:16.0.1`
  - `com.google.mlkit:text-recognition-korean:16.0.1`
  - `com.google.mlkit:translate:17.0.3`
  - `org.jetbrains.kotlinx:kotlinx-coroutines-play-services:1.9.0`

## 2. Core System Architecture: Dual-Window Accessibility Overlay

Implement an `AccessibilityService` (`MangaTranslatorService`) configured in `res/xml/accessibility_service_config.xml` with:
- `android:accessibilityEventTypes="typeViewScrolled|typeWindowStateChanged|typeWindowContentChanged"`
- `android:accessibilityFeedbackType="feedbackGeneric"`
- `android:canTakeScreenshot="true"`
- `android:canRetrieveWindowContent="false"` (we do not need view tree inspection, keeping overhead zero)
- `android:notificationTimeout="50"`

When connected, `MangaTranslatorService` manages two separate `WindowManager` overlay views using `WindowManager.LayoutParams.TYPE_ACCESSIBILITY_OVERLAY`:

### Window A: `TranslationCanvasView` (Full-Screen Passthrough Render Layer)
- **Dimensions**: `MATCH_PARENT` x `MATCH_PARENT`.
- **Flags**:
  `FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCHABLE or FLAG_LAYOUT_IN_SCREEN or FLAG_LAYOUT_NO_LIMITS`
- **Cutout Mode**: `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`.
- **Format**: `PixelFormat.TRANSLUCENT`.
- **Behavior**: Because `FLAG_NOT_TOUCHABLE` is set, 100% of user taps, swipes, and pinch-zooms pass straight through the translated speech bubbles into the underlying manga reader app.

### Window B: `FloatingControlPillView` (Edge Controller & Hardware Touch-Down Sensor)
- **Dimensions**: `WRAP_CONTENT` x `WRAP_CONTENT`.
- **Flags**:
  `FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCH_MODAL or FLAG_WATCH_OUTSIDE_TOUCH or FLAG_LAYOUT_IN_SCREEN`
- **Format**: `PixelFormat.TRANSLUCENT`.
- **Crucial Touch Detection Mechanism**:
  Because `FLAG_WATCH_OUTSIDE_TOUCH` is enabled on this window, any touch event anywhere on the screen outside the pill immediately delivers a `MotionEvent.ACTION_OUTSIDE` event to `FloatingControlPillView.onTouchEvent()` without consuming or blocking the user's swipe in the manga app underneath.
- **Pill Controls**:
  - **Drag**: Smoothly drags along screen bounds and snaps to the nearest left or right screen edge on `ACTION_UP`.
  - **Single Tap**:
    - In **Auto Mode**: Forces an immediate re-scan or toggles pause.
    - In **Manual Mode**: Triggers a single screen capture and translation pass.
  - **Long Press / Compact Menu Expand**: Cycles source script (`JA` -> `ZH` -> `KO`) and toggles mode (`AUTO` / `MANUAL` / `OFF`) with clear visual badge indicators on the pill.

## 3. Touch-Settle & Scroll Debounce State Machine

Implement a deterministic coroutine state machine inside `TranslationCoordinator`:

1. **Instant Hide on User Interaction**:
   - The exact millisecond `FloatingControlPillView` receives `MotionEvent.ACTION_OUTSIDE` OR `MangaTranslatorService.onAccessibilityEvent()` receives `TYPE_VIEW_SCROLLED` / `TYPE_WINDOW_STATE_CHANGED`:
   - Immediately clear/hide `TranslationCanvasView` (`visibility = View.INVISIBLE`) on `Dispatchers.Main.immediate` so the user sees raw artwork moving with zero ghosting.
   - Cancel any in-flight OCR/translation coroutine job.
   - If in `AUTO` mode, start or reset a debounce coroutine timer (`settleDelayMs = 450L` default, configurable 250ms to 1000ms).

2. **API-Level Screenshot Cooldown Handling**:
   - Track `lastScreenshotTimestampMs`.
   - On Android 11 and 12 (`Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU`), Android enforces a strict 1000ms minimum interval between `takeScreenshot()` calls (`ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT`). Dynamically pad the debounce delay so `now - lastScreenshotTimestampMs >= 1050L` on API 30-32.
   - On Android 13 through Android 16 (`API 33 - 36`), allow the full 450ms settle speed. Also handle `AccessibilityService.ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT` gracefully with a single delayed retry (350ms) on all API levels.

3. **Self-Occlusion Prevention**:
   - Before invoking `takeScreenshot(Display.DEFAULT_DISPLAY, executor, callback)`, verify `TranslationCanvasView.visibility == View.INVISIBLE`.
   - If it was visible (e.g., manual re-scan), set it `INVISIBLE` and await one `Choreographer.getInstance().postFrameCallback` before calling `takeScreenshot()` so the service never OCRs its own English overlays.

4. **HardwareBuffer Lifecycle & Fast 64-bit dHash Cache**:
   - Wrap the returned `ScreenshotResult.hardwareBuffer` via `Bitmap.wrapHardwareBuffer(buffer, colorSpace)` and copy it to a software `Bitmap.Config.ARGB_8888` inside a `try / finally` block that always calls `hardwareBuffer.close()`.
   - Mask out or ignore the bounding rectangle of `FloatingControlPillView`.
   - Compute a 64-bit perceptual difference hash (`dHash`) by downsampling the bitmap to `9x8` grayscale pixels and comparing adjacent horizontal intensities (takes < 1ms).
   - Compare the new `dHash` against `previousFrameDHash` using `Long.lang.bitCount(newHash xor oldHash)` (Hamming distance).
   - If `hammingDistance <= 3` and cached `List<TranslatedBubble>` exists for the current source language, skip OCR and translation completely and immediately re-render the cached bubbles.

## 4. Manga Speech Bubble Clustering & Vertical Text Engine

Raw ML Kit OCR splits vertical Japanese (`tategaki`) and multi-line Korean/Chinese bubbles into separate `Text.Line` objects. Translating line-by-line produces broken nonsense. Implement `SpeechBubbleClusterer` to merge lines into full speech bubbles before translation:

1. **Line Extraction & Filtering**:
   - Extract all `Text.Line` objects from ML Kit's `Text` result.
   - Discard noise boxes where `min(rect.width(), rect.height()) < 14px` or where text consists exclusively of ASCII punctuation/symbols.

2. **Orientation Classification**:
   - Mark a `Line` as `VERTICAL` if `rect.height() > rect.width() * 1.35f` and `line.text.length >= 2`. Otherwise mark as `HORIZONTAL`.
   - Estimate character unit size:
     - For `VERTICAL`: `charSize = rect.width().toFloat()`
     - For `HORIZONTAL`: `charSize = rect.height().toFloat()`

3. **Union-Find (Disjoint Set) Spatial + Ink-Boundary Merging**:
   - Merge two lines `A` and `B` into the same cluster if all three conditions hold:
     - **Condition 1 (Orientation compatibility)**: Both share the same orientation, OR one line is a single character (`length == 1`) adjacent to the other.
     - **Condition 2 (Spatial proximity)**:
       - If predominantly `VERTICAL`: horizontal gap between `rectA` and `rectB` is `< 1.85f * max(charSizeA, charSizeB)` AND vertical projection overlap ratio (`overlapY / min(heightA, heightB)`) is `> 0.30f`.
       - If predominantly `HORIZONTAL`: vertical gap between `rectA` and `rectB` is `< 1.65f * max(charSizeA, charSizeB)` AND horizontal projection overlap ratio (`overlapX / min(widthA, widthB)`) is `> 0.30f`.
     - **Condition 3 (Speech Bubble Ink-Wall Check)**:
       - Sample 7 evenly spaced pixels along the segment connecting the inner edges of `rectA` and `rectB` in the captured `Bitmap`.
       - Compute the background luminance at the perimeter of `rectA` and `rectB`. If the segment between `rectA` and `rectB` crosses a high-contrast dark ink border followed by white gutter space (indicating two separate adjacent speech bubbles), reject the merge.

4. **Reading-Order Sorting & String Assembly**:
   - For each merged cluster:
     - If the majority of lines are `VERTICAL` (standard Japanese manga): sort lines **Right-to-Left** (`sortedByDescending { it.boundingBox.centerX() }`). Concatenate their strings directly without spaces, stripping trailing CJK hyphenation dashes.
     - If the majority of lines are `HORIZONTAL` (manhwa / manhua): sort lines **Top-to-Bottom** (`sortedBy { it.boundingBox.centerY() }`). Concatenate strings cleanly.
   - Compute the cluster's bounding box `unionRect` as the union of all member line bounding boxes.

## 5. On-Device Translation & Background Color Sampling

1. **Batch Concurrent Translation**:
   - Maintain singleton/cached instances of `TextRecognizer` (Japanese, Chinese, Korean) and `Translator` (`TranslateLanguage.JAPANESE / CHINESE / KOREAN` -> `TranslateLanguage.ENGLISH`, plus user-selectable target language).
   - Ensure `translator.downloadModelIfNeeded()` is managed with clear progress state in the main Activity and verified before translation.
   - Maintain an in-memory `LruCache<String, String>(500)` mapping normalized source CJK text to translated text so repeated SFX, character names, and UI strings translate in 0ms.

2. **Adaptive Bubble Background & Text Color Sampling**:
   - For each `SpeechBubbleCluster`, sample 24 perimeter pixels just inside and 3px outside `unionRect` in the source `Bitmap`.
   - Compute the 75th-percentile luminance color to capture the speech bubble's paper/fill color while ignoring black glyph ink.
   - Set `bubbleFillColor` to that sampled color (with alpha `248`), and set `textColor` to `#121212` if sampled luminance `> 0.45f`, or `#F4F4F4` if sampled luminance `<= 0.45f` (for dark flashback panels or black narrator boxes).

## 6. Auto-Sizing Typography Renderer (`TranslationCanvasView`)

Inside `TranslationCanvasView.onDraw(canvas: Canvas)`:
1. Expand each bubble's `unionRect` by `4dp` padding and draw a rounded rectangle (`cornerRadius = 8dp`) using `bubbleFillColor`, plus a subtle `1dp` stroke at 15% contrast so overlapping boxes stay legible.
2. **Binary-Search Font Sizing with `StaticLayout`**:
   - Given the translated text and target padded width/height, binary-search `TextPaint.textSize` between `9sp` and `22sp` (5 iterations) using `StaticLayout.Builder.obtain(...)` (`Layout.Alignment.ALIGN_CENTER`, `lineSpacingMultiplier = 0.95f`).
   - Pick the largest font size where `staticLayout.height <= paddedRect.height()`.
   - If even `9sp` overflows `paddedRect.height()` (common when narrow vertical Japanese columns translate into longer horizontal English sentences), expand the render box horizontally by up to `20%` and vertically from the center to fit the `9sp` `StaticLayout` so words are never clipped.
3. Center the `StaticLayout` vertically and horizontally inside the final render box and draw it onto the `Canvas`.
